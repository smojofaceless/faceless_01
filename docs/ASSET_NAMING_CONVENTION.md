# Asset Storage & Naming Convention

> **Document Version:** 1.0  
> **Last Updated:** February 22, 2026  
> **Related:** Roadmap Item #8

---

## Overview

This document defines the canonical storage paths, asset types, and idempotency key conventions for all artifacts generated by the worker-v1 pipeline.

---

## Storage Bucket

All assets are stored in the `story-videos` Supabase Storage bucket.

---

## Path Convention

```
brands/{brand_id}/jobs/{job_id}/{category}/{filename}
```

### Category Directories

| Category | Purpose | Example Files |
|----------|---------|---------------|
| `images/` | Per-scene generated images | `scene_00.png`, `scene_01.png` |
| `audio/` | Voice narration | `narration.mp3` |
| `subtitles/` | Subtitle files | `captions.srt` |
| `video/` | Assembled and final video | `assembled.mp4`, `final.mp4` |

### Full Path Examples

```
brands/abc123/jobs/job456/images/scene_00.png
brands/abc123/jobs/job456/images/scene_01.png
brands/abc123/jobs/job456/images/scene_02.png
brands/abc123/jobs/job456/audio/narration.mp3
brands/abc123/jobs/job456/subtitles/captions.srt
brands/abc123/jobs/job456/video/assembled.mp4
brands/abc123/jobs/job456/video/final.mp4
```

---

## Asset Type Taxonomy

| Type | Description | Has Storage? | Step |
|------|-------------|--------------|------|
| `story` | Generated story content | No (data in job) | story |
| `uniqueness_check` | Story uniqueness verification | No (metadata) | uniqueness |
| `scene_data` | Scene breakdown + subtitle cues JSON | No (metadata) | scenes |
| `voice_audio` | Narration audio from ElevenLabs | Yes | voice |
| `music` | Music track selection (metadata) | No | music |
| `scene_image` | Per-scene generated image | Yes | images |
| `subtitles` | SRT subtitle file | Yes | subtitles |
| `assembled_video` | Video from renderer (temp) | Yes (external URL or stored) | assemble |
| `final_video` | Final video in permanent storage | Yes | upload |
| `post_schedule` | Post scheduling metadata | No | schedule |

### Hash-Based Types (External Idempotency)

| Type | Purpose | Key Pattern |
|------|---------|-------------|
| `voice_audio` | Billing protection (same text → same audio) | `voice_hash:{hash}` |
| `scene_image` | Billing protection (same prompt → same image) | `image_hash:{hash}` |

---

## Idempotency Keys

Each asset has a unique idempotency key that enables:
1. **Step idempotency**: Re-running a step won't duplicate work
2. **Cross-job deduplication**: Same prompt hash can reuse existing image
3. **Audit trail**: Clear mapping from key to what was generated

### Key Patterns

| Step | Primary Key | Hash Key (if applicable) |
|------|-------------|--------------------------|
| story | `{job_id}:story_generate` | - |
| uniqueness | `{job_id}:uniqueness_check` | - |
| scenes | `{job_id}:scenes_subtitles` | - |
| voice | `{job_id}:voice_synthesis` | `voice_hash:{content_hash}` |
| music | `{job_id}:music_select` | - |
| images | `{job_id}:image_generate:scene_{NN}` | `image_hash:{prompt_hash}` |
| subtitles | `{job_id}:subtitle_generation` | - |
| assemble | `{job_id}:video_assemble` | - |
| upload | `{job_id}:upload_storage` | - |
| schedule | `{job_id}:schedule_post` | - |

### Scene Index Formatting

Scene indices are zero-padded to 2 digits for proper sorting:
- `scene_00`, `scene_01`, ..., `scene_09`, `scene_10`, ...

## job_assets Table Schema

```sql
job_assets (
  id UUID PRIMARY KEY,
  job_id UUID NOT NULL REFERENCES jobs(id),
  type TEXT NOT NULL,
  idempotency_key TEXT NOT NULL,
  storage_path TEXT,           -- Path within bucket (null for metadata-only)
  public_url TEXT,             -- Public URL (null for metadata-only)
  meta JSONB DEFAULT '{}',     -- Asset-specific metadata
  content_hash TEXT,           -- Hash of content (for dedup)
  quality_ok BOOLEAN DEFAULT TRUE,  -- Quality flag
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  
  UNIQUE(job_id, idempotency_key)
)
```

## Path Builder Functions

The worker uses centralized path builder functions in `helpers.ts`:

```typescript

  → "brands/{brandId}/jobs/{jobId}/images/scene_{NN}.png"

pathForAudio(brandId, jobId) 
  → "brands/{brandId}/jobs/{jobId}/audio/narration.mp3"

  → "brands/{brandId}/jobs/{jobId}/subtitles/captions.srt"

pathForAssembledVideo(brandId, jobId) 
  → "brands/{brandId}/jobs/{jobId}/video/assembled.mp4"

pathForFinalVideo(brandId, jobId) 
  → "brands/{brandId}/jobs/{jobId}/video/final.mp4"
```

## Backwards Compatibility

### Old Path Format
```
jobs/{job_id}/images/scene_{N}.png
jobs/{job_id}/audio/narration.mp3
```

### Migration Strategy
1. **New jobs**: Use new `brands/{brand_id}/...` convention
2. **Existing assets**: Continue to work (URLs stored in job_assets.public_url)
3. **No data migration needed**: Old URLs remain valid
4. **Gradual transition**: All new runs use new paths

---

## Verification Guard

The finalization barrier (`verifyJobAssetsComplete`) checks:

1. ✓ Voice audio exists with `public_url` and `quality_ok !== false`
2. ✓ All scene images exist (count matches scene_data)
3. ✓ Subtitles SRT exists with `public_url`
4. ✓ Final video exists (`job.video_url` populated)
5. ✓ Posts scheduled for requested platforms

Jobs cannot be marked `complete` until all checks pass.

## Required Assets by Step

| Step | Must Create |
|------|-------------|
| story | `story` asset with title, content_hash |
| uniqueness | `uniqueness_check` asset with similarity score |
| scenes | `scene_data` asset with scenes array, subtitle_cues |
| voice | `voice_audio` asset with storage path, duration |
| music | `music` asset with track_id |
| images | N × `scene_image` assets (one per scene) |
| subtitles | `subtitles` asset with storage path |
| assemble | `assembled_video` asset with video URL |
| upload | `final_video` asset with permanent storage path |
| schedule | `post_schedule` asset with results |

---

## Idempotency Guarantees

1. **Step re-runs**: If asset exists with same idempotency_key, step is skipped
2. **Hash lookups**: Before expensive API calls, check for hash-based asset
3. **Storage upserts**: All uploads use `upsert: true` for atomic create-or-replace
4. **RPC atomicity**: `upsert_job_asset` is idempotent (INSERT ON CONFLICT DO UPDATE)
